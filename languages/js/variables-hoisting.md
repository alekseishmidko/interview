# `var`, `let`, `const`, hoisting и области видимости — подготовка к интервью

## Короткий ответ для собеседования

`var`, `let` и `const` создают привязки имён к значениям, но отличаются областью видимости, возможностью повторного объявления и моментом инициализации.

- `var` имеет функциональную или глобальную область видимости, допускает повторное объявление и при входе в область сразу инициализируется значением `undefined`.
- `let` имеет блочную область видимости, запрещает повторное объявление в одном scope и позволяет переприсваивание.
- `const` тоже имеет блочную область видимости, требует инициализации и запрещает переприсваивать саму привязку. Содержимое объекта при этом может изменяться.

Все объявления обрабатываются до пошагового выполнения кода — это обычно называют **hoisting**. При этом `var` доступен до строки объявления как `undefined`, объявления функций доступны вместе с телом функции, а `let`, `const` и `class` до инициализации находятся в **Temporal Dead Zone** и при обращении вызывают `ReferenceError`.

В современном коде обычно используют `const` по умолчанию, `let` — когда значение переменной должно меняться, а `var` оставляют для поддержки старого кода или вопросов совместимости.

# Часть I. Основы

## 1. Переменная, значение и привязка

Удобнее говорить не «переменная хранит объект», а «идентификатор связан со значением».

```js
const user = { name: "Alex" };
```

Здесь:

- `user` — идентификатор;
- `const` создаёт неизменяемую привязку;
- `{ name: "Alex" }` — объектное значение;
- привязку `user` нельзя направить на другой объект;
- сам объект остаётся изменяемым.

Нужно различать три операции:

```js
let count;      // объявление
count = 1;      // присваивание

let total = 10; // объявление + инициализация
```

- **объявление** сообщает движку о существовании имени;
- **инициализация** впервые присваивает привязке значение;
- **переприсваивание** меняет значение уже инициализированной изменяемой привязки.

## 2. Сравнение `var`, `let` и `const`

| Характеристика | `var` | `let` | `const` |
|---|---|---|---|
| Область видимости | Функция или глобальная область | Блок | Блок |
| Доступ до строки объявления | `undefined` | `ReferenceError` | `ReferenceError` |
| Temporal Dead Zone | Нет в обычном смысле | Да | Да |
| Повторное объявление в одном scope | Разрешено | Запрещено | Запрещено |
| Переприсваивание | Разрешено | Разрешено | Запрещено |
| Инициализатор обязателен | Нет | Нет | Да, кроме заголовков `for...of`/`for...in` |
| Свойство глобального объекта в обычном script | Обычно да | Нет | Нет |

Базовая рекомендация:

```js
const apiUrl = "/api"; // значение привязки не меняется
let page = 1;           // будет переприсваиваться
```

`const` лучше использовать не потому, что значение «навсегда константа», а потому что отсутствие переприсваивания упрощает чтение и анализ кода.

## 3. Области видимости

**Scope — область видимости** — часть программы, в которой доступен идентификатор.

Основные виды:

- глобальная область;
- модульная область;
- функциональная область;
- блочная область;
- область параметров функции;
- область `catch`.

### Глобальная область

```js
const appName = "Store";

function start() {
  console.log(appName);
}
```

### Функциональная область

```js
function calculate() {
  var subtotal = 100;
  let tax = 20;
  const total = subtotal + tax;
}

console.log(subtotal); // ReferenceError
```

Все три имени недоступны за пределами функции.

### Блочная область

Блок создаётся фигурными скобками в `if`, `for`, `while`, `switch`, `try` или просто отдельной парой `{}`.

```js
if (true) {
  var functionScoped = "var";
  let blockScoped = "let";
  const alsoBlockScoped = "const";
}

console.log(functionScoped);  // "var"
console.log(blockScoped);     // ReferenceError
console.log(alsoBlockScoped); // ReferenceError
```

`var` игнорирует обычный блок и ограничивается ближайшей функцией или глобальной областью. `let`, `const` и `class` ограничиваются блоком.

## 4. Лексическая область видимости и цепочка scope

JavaScript использует лексическую область видимости: доступность имени определяется местом, где функция **объявлена**, а не местом, где она вызвана.

```js
const value = "global";

function outer() {
  const value = "outer";

  function inner() {
    console.log(value);
  }

  return inner;
}

const inner = outer();

function run(callback) {
  const value = "run";
  callback();
}

run(inner); // "outer"
```

При поиске `value` движок проверяет текущую лексическую среду, затем внешнюю и продолжает до глобальной области. Эта последовательность называется **цепочкой областей видимости**.

## 5. Shadowing — затенение

Внутренняя переменная может скрыть одноимённую внешнюю:

```js
const status = "global";

function check() {
  const status = "local";
  console.log(status); // "local"
}

check();
console.log(status); // "global"
```

Это разрешено, если объявления находятся в разных областях. Но чрезмерное затенение ухудшает читаемость.

### TDZ начинается в начале внутренней области

```js
const price = 100;

{
  console.log(price); // ReferenceError
  const price = 200;
}
```

Внутренний `price` затеняет внешний с начала блока, но ещё не инициализирован. Поэтому движок не переходит к внешнему `price`, а выбрасывает ошибку.

# Часть II. Hoisting и TDZ

## 6. Что такое hoisting

**Hoisting** — разговорная модель, описывающая эффект предварительной обработки объявлений перед выполнением строк программы.

Движок не переставляет исходные строки физически. Упрощённо выполнение контекста состоит из двух этапов:

1. Создаются окружение и привязки объявленных имён.
2. Инструкции выполняются по порядку, включая инициализации и присваивания.

Поэтому следующий код:

```js
console.log(value); // undefined
var value = 10;
```

можно мысленно представить так:

```js
var value;          // привязка уже создана и получила undefined
console.log(value); // undefined
value = 10;         // присваивание остаётся на своём месте
```

Это только учебная модель. Спецификация описывает создание привязок через Environment Records и алгоритмы инициализации объявлений.

## 7. Hoisting `var`

```js
function example() {
  console.log(value); // undefined
  var value = 42;
  console.log(value); // 42
}
```

При создании контекста функции привязка `value` уже существует и инициализирована `undefined`. До строки `var value = 42` ошибки нет, но значение ещё не присвоено.

### Объявление в недостижимом блоке

```js
function example() {
  console.log(flag); // undefined

  if (false) {
    var flag = true;
  }
}
```

Блок не выполняется, но объявление `var flag` относится ко всей функции.

## 8. Hoisting `let` и `const`

```js
console.log(count); // ReferenceError
let count = 1;
```

Привязка `count` создаётся при входе в scope, но остаётся неинициализированной до выполнения декларации. Обращение к ней в этот промежуток вызывает `ReferenceError`.

Важно правильно отвечать на интервью:

> `let` и `const` тоже обрабатываются до выполнения кода, но не инициализируются значением `undefined`. До декларации они находятся в TDZ.

Неверное упрощение: «`let` и `const` вообще не hoistятся». Оно не объясняет затенение и TDZ.

## 9. Temporal Dead Zone

**TDZ — Temporal Dead Zone** — участок выполнения от входа в лексическую область до момента инициализации привязки `let`, `const` или `class`.

```js
{
  // TDZ для user начинается при входе в блок.
  console.log(user); // ReferenceError
  let user = "Alex"; // здесь user инициализируется
  console.log(user); // "Alex"
}
```

Название «temporal» подчёркивает, что граница определяется моментом выполнения, а не только расположением строк:

```js
function read() {
  return value;
}

let value = 10;
read(); // 10
```

Функция объявлена до `value`, но вызывается после инициализации, поэтому ошибки нет.

### `typeof` и TDZ

```js
typeof completelyMissing; // "undefined"

{
  typeof value; // ReferenceError
  let value = 1;
}
```

`typeof` безопасен для имени, которое вообще не объявлено, но не обходит TDZ существующей лексической привязки.

## 10. Hoisting функций

### Function declaration

Объявление функции доступно вместе с созданным объектом функции до своей строки:

```js
sayHello(); // "Hello"

function sayHello() {
  console.log("Hello");
}
```

### Function expression с `var`

```js
sayHello(); // TypeError: sayHello is not a function

var sayHello = function () {
  console.log("Hello");
};
```

Hoistится только привязка `var sayHello`, и до присваивания она равна `undefined`. Попытка вызвать `undefined` вызывает `TypeError`, а не `ReferenceError`.

### Function expression и arrow function с `let`/`const`

```js
sayHello(); // ReferenceError

const sayHello = () => {
  console.log("Hello");
};
```

Здесь действует TDZ привязки `sayHello`.

### Function declaration внутри блока

```js
if (condition) {
  function process() {}
}
```

Поведение блочных function declarations в старом нестрогом script-коде исторически имело особенности совместимости. В современном коде и модулях следует считать такую функцию блочно-ограниченной и не полагаться на её доступность снаружи блока.

## 11. Hoisting классов

```js
const user = new User(); // ReferenceError

class User {}
```

Привязка класса создаётся заранее, но остаётся в TDZ до выполнения объявления класса. В отличие от function declaration, класс нельзя использовать до декларации.

Class expression подчиняется правилам переменной, которой присваивается:

```js
const User = class {};
```

Внутреннее имя именованного class expression доступно только внутри класса:

```js
const User = class InternalUser {
  static getName() {
    return InternalUser.name;
  }
};

typeof InternalUser; // "undefined" — снаружи такого имени нет
```

## 12. Hoisting импортов

Статические `import` обрабатываются до выполнения тела модуля:

```js
console.log(apiUrl);
import { apiUrl } from "./config.js";
```

Импортированные привязки являются **live bindings**: они отражают изменение экспортируемой привязки в исходном модуле. Их нельзя переприсвоить в импортирующем модуле.

Однако циклические зависимости могут привести к обращению к импорту до его инициализации и вызвать `ReferenceError`. Поэтому порядок инициализации модулей всё ещё важен.

# Часть III. Подробно о `var`, `let` и `const`

## 13. Особенности `var`

### Функциональная область

```js
function example() {
  if (true) {
    var message = "Hello";
  }

  console.log(message); // "Hello"
}
```

### Повторное объявление

```js
var value = 1;
var value = 2;

console.log(value); // 2
```

Повторное объявление разрешено, что может скрывать ошибки и затруднять рефакторинг.

### Присваивание до объявления

```js
function example() {
  value = 10;
  var value;
  return value;
}
```

Это присваивание локальной `var`-переменной, потому что её объявление относится ко всей функции.

## 14. Особенности `let`

```js
let count;
console.log(count); // undefined

count = 1;
count = 2;
```

После выполнения `let count` переменная инициализируется `undefined`. До этой строки она находилась в TDZ.

Повторное объявление в том же scope запрещено:

```js
let count = 1;
let count = 2; // SyntaxError
```

Вложенное объявление разрешено:

```js
let count = 1;

{
  let count = 2;
  console.log(count); // 2
}

console.log(count); // 1
```

## 15. Особенности `const`

Обычное объявление `const` требует инициализатор:

```js
const limit = 10;
const missing; // SyntaxError
```

Привязку нельзя переприсвоить:

```js
const limit = 10;
limit = 20; // TypeError
```

Но объект не становится неизменяемым:

```js
const user = { name: "Alex" };

user.name = "Anna"; // разрешено
user.role = "admin"; // разрешено

user = {}; // TypeError
```

То же относится к массивам:

```js
const items = [];
items.push("book"); // разрешено
items = [];         // TypeError
```

### `Object.freeze()`

```js
const settings = Object.freeze({
  theme: "dark",
  nested: { enabled: true },
});

settings.theme = "light";          // не изменит верхний уровень
settings.nested.enabled = false;    // вложенный объект всё ещё изменяем
```

`Object.freeze()` неглубокий. Для глубокой неизменяемости нужны отдельная стратегия, рекурсивное замораживание или иммутабельные структуры. В строгом режиме попытка изменить замороженное свойство выбрасывает `TypeError`; в нестрогом может завершиться без изменения и без исключения.

## 16. Почему `const` используют по умолчанию

`const` сообщает читателю и инструментам, что имя не будет переназначено:

```js
const response = await fetch(url);
const data = await response.json();
```

Это не означает, что объект `data` неизменяем. Это означает только, что переменная `data` не получит другое значение.

Используйте `let`, когда переприсваивание является частью алгоритма:

```js
let total = 0;

for (const item of items) {
  total += item.price;
}
```

## 17. Объявления в циклах

### Проблема `var` и замыканий

```js
for (var i = 0; i < 3; i += 1) {
  setTimeout(() => console.log(i), 0);
}

// 3
// 3
// 3
```

Все callback-функции замыкают одну функциональную привязку `i`. К моменту их выполнения цикл завершён и `i === 3`.

### `let` создаёт привязку для каждой итерации

```js
for (let i = 0; i < 3; i += 1) {
  setTimeout(() => console.log(i), 0);
}

// 0
// 1
// 2
```

Для цикла с `let` спецификация создаёт отдельную привязку итерации, поэтому каждое замыкание видит своё значение.

### `const` в `for...of`

```js
for (const item of items) {
  console.log(item);
}
```

Это разрешено: каждая итерация получает новую привязку `item`. Но в классическом цикле нельзя изменить `const`-счётчик:

```js
for (const i = 0; i < 3; i += 1) {
  // TypeError при i += 1
}
```

## 18. Замыкания

Замыкание — функция вместе с доступом к лексическому окружению, в котором она была создана.

```js
function createCounter() {
  let count = 0;

  return function increment() {
    count += 1;
    return count;
  };
}

const counter = createCounter();

counter(); // 1
counter(); // 2
```

После завершения `createCounter` окружение не удаляется, потому что функция `increment` продолжает использовать `count`.

`let` и `const` не являются причиной замыканий сами по себе. Замыкания работают и с `var`, но блочные и поитерационные привязки `let` часто дают ожидаемое поведение.

## 19. `switch` и общая блочная область

Все `case` одного `switch` по умолчанию находятся в одном блоке:

```js
switch (status) {
  case "loading":
    const message = "Loading";
    break;

  case "success":
    const message = "Done"; // SyntaxError: повторное объявление
    break;
}
```

Добавьте отдельные блоки:

```js
switch (status) {
  case "loading": {
    const message = "Loading";
    console.log(message);
    break;
  }

  case "success": {
    const message = "Done";
    console.log(message);
    break;
  }
}
```

## 20. `catch` и область ошибки

```js
try {
  throw new Error("Failed");
} catch (error) {
  console.log(error.message);
}

console.log(error); // ReferenceError
```

Параметр `catch` доступен только внутри блока `catch`.

## 21. Деструктуризация и объявления

```js
const { id, name: userName = "Anonymous" } = user;
const [first, second] = items;
let { page, limit } = params;
```

Здесь одновременно создаётся несколько привязок. Для `const` все они неизменяемы в смысле переприсваивания.

При присваивании существующим переменным объектную деструктуризацию заключают в скобки:

```js
let name;
({ name } = user);
```

Без скобок `{}` интерпретируется как блок.

# Часть IV. Глобальная область и модули

## 22. Глобальный `var` и `globalThis`

В обычном браузерном `<script>` верхнеуровневый `var` обычно создаёт свойство глобального объекта:

```html
<script>
  var oldValue = 1;
  let modernValue = 2;
  const fixedValue = 3;

  console.log(window.oldValue);    // 1
  console.log(window.modernValue); // undefined
  console.log(window.fixedValue);  // undefined
</script>
```

Глобальные `let`, `const` и `class` находятся в глобальном лексическом окружении, но не становятся свойствами `window`.

Для переносимой ссылки на глобальный объект используют `globalThis`:

```js
globalThis.setTimeout;
```

Этот пример относится именно к классическому браузерному script. В Node.js CommonJS файл обёрнут модульной функцией, а ES-модуль имеет собственную модульную область.

## 23. ES-модули

```html
<script type="module" src="app.js"></script>
```

В ES-модуле:

- верхнеуровневые объявления принадлежат модулю и не добавляются в `globalThis`;
- код всегда выполняется в строгом режиме;
- каждое имя можно экспортировать и импортировать;
- статические импорты анализируются до выполнения;
- случайное присваивание необъявленному имени вызывает `ReferenceError`.

```js
// config.js
export const apiUrl = "/api";

// app.js
import { apiUrl } from "./config.js";
```

## 24. Необъявленные переменные

```js
function legacy() {
  accidentalGlobal = 42;
}
```

В старом нестрогом script-коде такое присваивание может создать свойство глобального объекта. Это не объявление `var` и считается ошибкой проектирования.

В strict mode и ES-модулях будет `ReferenceError`:

```js
"use strict";
accidentalGlobal = 42; // ReferenceError
```

Использование линтера с правилами `no-undef`, `no-var` и `prefer-const` помогает находить такие ошибки.

## 25. `delete` и объявления

Оператор `delete` предназначен для свойств объектов, а не для обычных лексических привязок:

```js
const user = { name: "Alex" };
delete user.name; // удаление свойства
```

Объявленную переменную нельзя надёжно «удалить» через `delete`. Глобальный `var` в script обычно создаёт неконфигурируемое свойство, тогда как случайно созданное глобальное свойство в нестрогом режиме может вести себя иначе. Не следует строить прикладную логику на таких различиях.

# Часть V. Сопутствующие механизмы

## 26. Execution Context

При запуске script, модуля или функции движок создаёт **контекст выполнения**. В упрощённой модели он содержит:

- лексическое окружение с привязками;
- внешнюю ссылку для цепочки scope;
- информацию о `this`;
- данные, необходимые для выполнения функции или модуля.

```js
const globalValue = 1;

function sum(a, b) {
  const result = a + b + globalValue;
  return result;
}

sum(2, 3);
```

При вызове `sum` создаётся новый функциональный контекст с параметрами `a`, `b` и локальной привязкой `result`. Через внешнее окружение функция находит `globalValue`.

Термин «фаза создания, затем фаза выполнения» полезен на интервью как модель, но не стоит приписывать движку буквальное копирование кода или конкретное внутреннее устройство памяти.

## 27. Lexical Environment и Environment Record

На уровне спецификации окружение связывает код с **Environment Record**, который хранит привязки имён, и ссылкой на внешнее окружение.

Разные объявления могут обслуживаться разными записями окружения:

- декларативными — для `let`, `const`, классов и большинства локальных имён;
- функциональными — для вызова функции и параметров;
- модульными — для верхнего уровня модуля и импортов;
- глобальными — для глобального script-кода и глобального объекта.

На интервью обычно достаточно объяснить: «scope chain формируется лексическими окружениями; движок ищет имя от текущего окружения к внешним».

## 28. Параметры по умолчанию

Параметры по умолчанию вычисляются слева направо и могут использовать ранее объявленные параметры:

```js
function createRange(start, end = start + 1) {
  return [start, end];
}
```

Но тело функции ещё не выполнилось:

```js
function example(value = localValue) {
  const localValue = 10;
  return value;
}

example(); // ReferenceError
```

Параметр по умолчанию не видит локальную переменную тела функции в момент своей инициализации.

## 29. IIFE и историческое ограничение `var`

До появления блочных переменных для создания отдельной области часто использовали IIFE:

```js
(function () {
  var privateValue = 42;
})();

console.log(privateValue); // ReferenceError
```

Сейчас для локальной блочной области обычно достаточно:

```js
{
  const privateValue = 42;
}
```

IIFE всё ещё может применяться для немедленного вычисления или изоляции старого script-кода, но модули и блочные объявления закрывают большинство прежних сценариев.

## 30. `var` и function declaration с одним именем

```js
console.log(typeof value); // "function"

var value = 1;

function value() {}

console.log(value); // 1
```

При создании окружения function declaration предоставляет функцию. Затем во время выполнения присваивание из `var value = 1` заменяет текущее значение. Подобные конфликты разрешены историческими правилами, но их нужно избегать.

## 31. Недопустимое затенение

Нельзя объявить `var` так, чтобы оно конфликтовало с лексической привязкой в охватывающей части той же функции:

```js
let value = 1;

{
  var value = 2; // SyntaxError
}
```

`var` пытается принадлежать внешней функциональной или глобальной области и пересекается с `let value`.

Обратное вложенное затенение допустимо:

```js
var value = 1;

{
  let value = 2;
  console.log(value); // 2
}
```

## 32. Сборщик мусора и область видимости

Выход из блока или функции не означает немедленное освобождение памяти. Значение может оставаться достижимым через:

- возвращённое замыкание;
- объект или массив;
- обработчик события;
- таймер;
- внешний кэш.

```js
function createHandler(largeData) {
  return () => console.log(largeData.id);
}

const handler = createHandler({ id: 1, payload: new Array(100_000) });
```

Пока `handler` достижим и действительно удерживает окружение с объектом, данные могут оставаться в памяти. Выбор `let` вместо `var` сам по себе не предотвращает утечки.

# Часть VI. Вопросы для интервью

## 33. Чем `var` отличается от `let`?

`var` имеет функциональную область, допускает повторное объявление и инициализируется `undefined` при создании контекста. `let` имеет блочную область, запрещает повторное объявление в одном scope и до декларации находится в TDZ.

## 34. Чем `let` отличается от `const`?

Обе декларации блочные и имеют TDZ. `let` можно переприсваивать, а `const` — нельзя. Кроме того, обычный `const` требует инициализатор при объявлении.

## 35. Делает ли `const` объект неизменяемым?

Нет. `const` защищает привязку, а не объект. Свойства объекта и элементы массива можно изменять. Для поверхностного запрета изменений существует `Object.freeze()`.

## 36. Что hoistится в JavaScript?

Предварительно обрабатываются все объявления, но по-разному:

- `var` создаётся и получает `undefined`;
- function declaration создаётся вместе с функцией;
- `let`, `const` и `class` создаются, но остаются неинициализированными в TDZ;
- function expression следует правилам переменной, которой присваивается;
- статические импорты связываются до выполнения модуля.

## 37. Почему `let` считается hoisted, если его нельзя прочитать заранее?

Потому что привязка существует с начала scope и затеняет внешние имена, но ещё не инициализирована. Именно существование неинициализированной привязки создаёт TDZ и `ReferenceError`.

## 38. Чем `undefined` отличается от `ReferenceError` до объявления?

`var` уже существует и инициализирован `undefined`, поэтому чтение разрешено. Привязка `let` или `const` существует, но не инициализирована, поэтому доступ запрещён и возникает `ReferenceError`.

## 39. Почему function declaration можно вызвать раньше?

При создании окружения для объявления создаётся и инициализируется объект функции. У function expression инициализация происходит только при выполнении выражения присваивания.

## 40. Что выведет цикл с `var` и `setTimeout`?

Обычно несколько одинаковых конечных значений, потому что callback-функции замыкают одну привязку. `let` в заголовке цикла создаёт отдельную привязку для каждой итерации.

## 41. Становится ли глобальный `let` свойством `window`?

Нет. В обычном браузерном script верхнеуровневый `var` обычно связан со свойством глобального объекта, а `let`, `const` и `class` находятся в отдельной декларативной части глобального окружения. В ES-модулях верхнеуровневые объявления модульные.

## 42. Что выбирать в новом коде?

`const` по умолчанию, `let` при необходимом переприсваивании. `var` обычно не нужен, кроме поддержки или анализа старого кода.

# Часть VII. Практические задачи

## 43. Задача: базовый hoisting

```js
console.log(a);
var a = 5;
console.log(a);
```

**Ответ:** сначала `undefined`, затем `5`. Объявление `a` создано и инициализировано заранее, но присваивание `5` выполняется на своей строке.

## 44. Задача: `let` и TDZ

```js
console.log(a);
let a = 5;
```

**Ответ:** `ReferenceError` на первой строке. Привязка `a` уже существует, но ещё не инициализирована.

## 45. Задача: затенение и TDZ

```js
let value = "outer";

function example() {
  console.log(value);
  let value = "inner";
}

example();
```

**Ответ:** `ReferenceError`. Внутренний `value` затеняет внешний во всей функции, но до декларации находится в TDZ.

## 46. Задача: функции

```js
console.log(typeof declaration);
console.log(typeof expression);

function declaration() {}
var expression = function () {};
```

**Ответ:** `"function"`, затем `"undefined"`. Function declaration инициализирована функцией заранее; `var expression` пока содержит `undefined`.

## 47. Задача: `const` и объект

```js
const user = { name: "Alex" };
user.name = "Anna";
user = { name: "John" };
```

**Ответ:** изменение `user.name` разрешено. Переприсваивание `user` вызывает `TypeError`.

## 48. Задача: цикл и замыкание

```js
const callbacks = [];

for (var i = 0; i < 3; i += 1) {
  callbacks.push(() => i);
}

console.log(callbacks.map((callback) => callback()));
```

**Ответ:** `[3, 3, 3]`. Все функции используют одну привязку `i`.

Исправление:

```js
const callbacks = [];

for (let i = 0; i < 3; i += 1) {
  callbacks.push(() => i);
}

console.log(callbacks.map((callback) => callback())); // [0, 1, 2]
```

## 49. Задача: `typeof`

```js
console.log(typeof missing);
console.log(typeof value);
let value = 1;
```

**Ответ:** первая строка выводит `"undefined"`. Вторая вызывает `ReferenceError`, и выполнение прекращается, потому что `value` находится в TDZ.

## 50. Задача: область блока

```js
function test() {
  if (true) {
    var a = 1;
    let b = 2;
    const c = 3;
  }

  console.log(a);
  console.log(b);
  console.log(c);
}
```

**Ответ:** выводится `1`, затем возникает `ReferenceError` при чтении `b`. До чтения `c` выполнение не доходит.

## 51. Задача: синхронный цикл

```js
for (var i = 0; i < 3; i += 1) {
  console.log(i);
}
```

**Ответ:** `0`, `1`, `2`. Проблема одинакового значения возникает не из-за самого `var`, а когда функции обращаются к общей привязке позже, например из таймера.

## 52. Задача: function и `var`

```js
console.log(value);

var value = 10;

function value() {
  return 20;
}

console.log(value);
```

**Ответ:** сначала выводится функция, затем `10`. Function declaration инициализирует привязку до выполнения, а присваивание `value = 10` выполняется позже по порядку.

## 53. Задача: параметры по умолчанию

```js
const value = 1;

function test(value = value) {
  return value;
}

test();
```

**Ответ:** `ReferenceError`. Имя параметра `value` уже затеняет внешнюю переменную, но его значение ещё вычисляется и привязка не инициализирована. Это пример TDZ внутри области параметров.

## 54. Задача: переписать старый код

Исходный вариант:

```js
var result = [];

for (var i = 0; i < items.length; i += 1) {
  var item = items[i];
  result.push(item.id);
}
```

Современный вариант:

```js
const result = [];

for (const item of items) {
  result.push(item.id);
}
```

`result` объявлен через `const`, потому что массив не переприсваивается. Его содержимое изменять можно.

## 55. Готовый развёрнутый ответ

> В JavaScript `var`, `let` и `const` создают привязки имён, но имеют разные правила. `var` ограничен функцией или глобальной областью, допускает повторное объявление и при создании контекста сразу инициализируется `undefined`. `let` и `const` имеют блочную область, не допускают повторного объявления в одном scope и остаются неинициализированными до своей декларации. Этот интервал называется Temporal Dead Zone.
>
> Hoisting — не буквальное перемещение строк вверх, а результат предварительного создания привязок перед выполнением кода. Function declaration создаётся вместе с функцией, поэтому её можно вызвать заранее. Function expression подчиняется правилам переменной: с `var` до присваивания будет `undefined`, а с `let` или `const` — TDZ. Классы также находятся в TDZ, а статические импорты связываются до выполнения модуля.
>
> `const` запрещает переназначить привязку, но не делает объект неизменяемым. В цикле `let` создаёт привязку для каждой итерации, поэтому замыкания получают разные значения, тогда как `var` обычно даёт одну общую привязку. В современном коде я использую `const` по умолчанию, `let` при необходимом переприсваивании и избегаю `var`, если нет требований старого окружения.
