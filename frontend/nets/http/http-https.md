# HTTP и HTTPS

## Что такое HTTP

**HTTP (Hypertext Transfer Protocol)** — stateless-протокол прикладного уровня, построенный вокруг модели «запрос — ответ». Клиент отправляет сообщение с методом, URI, заголовками и, при необходимости, телом; сервер возвращает статус, заголовки и тело ответа.

```http
GET /api/users/42 HTTP/1.1
Host: example.com
Accept: application/json
```

```http
HTTP/1.1 200 OK
Content-Type: application/json
Content-Length: 25

{"id":42,"name":"Alex"}
```

HTTP не обязан передавать HTML. Через него передаются JSON, изображения, видео, файлы и другие представления ресурсов.

## Из чего состоит запрос

- метод: `GET`, `POST`, `PUT` и другие;
- URI ресурса;
- версия протокола в HTTP/1.x;
- заголовки;
- необязательное тело.

Частые заголовки запроса:

- `Host` — целевой хост;
- `Accept` — желаемый тип ответа;
- `Content-Type` — формат отправляемого тела;
- `Authorization` — данные авторизации;
- `Cookie` — подходящие cookies;
- `If-None-Match` — валидатор кеша.

## Из чего состоит ответ

- код статуса;
- reason phrase в HTTP/1.1;
- заголовки;
- необязательное тело.

Группы статусов:

| Группа | Значение | Примеры |
| --- | --- | --- |
| `1xx` | Информационный ответ | `100`, `103` |
| `2xx` | Успех | `200`, `201`, `204` |
| `3xx` | Перенаправление или работа с кешем | `301`, `302`, `304`, `307`, `308` |
| `4xx` | Ошибка клиента | `400`, `401`, `403`, `404`, `409`, `429` |
| `5xx` | Ошибка сервера | `500`, `502`, `503`, `504` |

## Stateless

HTTP сам по себе не требует, чтобы сервер помнил предыдущий запрос. Каждый запрос должен содержать достаточный контекст.

Состояние поверх HTTP реализуют через:

- cookies и серверные сессии;
- access-токены;
- идентификаторы ресурсов;
- данные в URL или теле запроса.

Stateless не означает, что приложение не может хранить состояние. Это характеристика базовой семантики протокола.

## HTTP и транспорт

HTTP — прикладной протокол. Способ транспортировки зависит от версии:

| Версия | Основной транспорт | Особенность |
| --- | --- | --- |
| HTTP/1.1 | TCP | Текстовый формат сообщений, persistent connections |
| HTTP/2 | TCP | Бинарный framing и мультиплексирование потоков |
| HTTP/3 | QUIC поверх UDP | Нет TCP head-of-line blocking между QUIC streams |

Семантика методов и статусов в основном сохраняется между версиями. Меняется способ кодирования и доставки сообщений.

## HTTP/1.1

- обычно повторно использует TCP-соединение;
- сообщения имеют текстовую стартовую строку и заголовки;
- несколько одновременных запросов часто требуют нескольких соединений;
- потеря TCP-пакета задерживает последующие байты соединения.

## HTTP/2

- бинарный протокол;
- разбивает сообщения на frames;
- мультиплексирует несколько streams внутри TCP-соединения;
- сжимает заголовки через HPACK;
- устраняет HTTP/1.1 head-of-line blocking на уровне запросов, но остаётся TCP head-of-line blocking при потере пакета.

## HTTP/3

- использует QUIC поверх UDP;
- каждый поток имеет собственную упорядоченную доставку;
- потеря данных одного потока не обязана блокировать остальные;
- TLS 1.3 интегрирован в QUIC;
- помогает быстрее устанавливать и восстанавливать соединение.

## Что такое HTTPS

**HTTPS** — HTTP, передаваемый через защищённый транспорт. Для HTTP/1.1 и HTTP/2 это обычно HTTP поверх TLS поверх TCP. HTTP/3 использует QUIC, в который интегрированы механизмы TLS 1.3.

HTTPS обеспечивает:

- конфиденциальность трафика;
- контроль целостности;
- аутентификацию сервера через сертификат;
- опциональную аутентификацию клиента.

HTTPS не гарантирует, что сервер честный или приложение не содержит уязвимостей. Он защищает канал связи и подтверждает связь сертификата с именем сервера.

## Порты

По умолчанию:

- HTTP — TCP port `80`;
- HTTPS — TCP port `443`;
- HTTP/3 обычно использует UDP port `443`.

Это значения по умолчанию, а не обязательные ограничения.

## Путь запроса

Упрощённо открытие `https://example.com/products` выглядит так:

1. Браузер разбирает URL.
2. Проверяет кеш и политики безопасности.
3. Разрешает имя через DNS.
4. Устанавливает транспортное соединение.
5. Выполняет TLS handshake для HTTPS.
6. Отправляет HTTP-запрос.
7. Сервер или промежуточный узел возвращает ответ.
8. Браузер применяет cookies, кеширование и обработку содержимого.

Часть шагов может быть пропущена благодаря DNS-кешу, повторному соединению, TLS resumption, CDN или HTTP-кешу.

## Типичные вопросы

### HTTP шифрует данные?

Нет. За защищённый канал в HTTPS отвечает TLS или встроенная в QUIC TLS-механика.

### Чем HTTP отличается от TCP?

HTTP задаёт смысл запросов и ответов на прикладном уровне. TCP предоставляет надёжный упорядоченный поток байтов транспортного уровня.

### HTTP/2 делает запросы параллельными?

Он мультиплексирует несколько HTTP streams в одном TCP-соединении. Но потеря TCP-сегмента может временно задержать все streams этого соединения.

### Почему HTTP/3 использует UDP?

QUIC реализует поверх UDP надёжность, контроль перегрузки, безопасность и независимые потоки, не наследуя ограничения единого TCP-потока.

### HTTPS защищает URL?

После установления защищённого соединения путь, query, заголовки и тело шифруются. Однако IP-адрес назначения и часть метаданных соединения могут оставаться наблюдаемыми; имя хоста также может быть раскрыто в зависимости от DNS и механизма ClientHello.

## Краткий ответ

> HTTP — stateless-протокол прикладного уровня с моделью request/response. HTTP/1.1 и HTTP/2 обычно работают поверх TCP, а HTTP/3 — поверх QUIC/UDP. HTTPS сохраняет семантику HTTP, но защищает транспорт с помощью TLS: обеспечивает шифрование, целостность и аутентификацию сервера.
